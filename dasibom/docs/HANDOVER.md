## 1. 무엇을 만들고 있나

중1 학생이 **수업 당일 집에서 혼자 복습**하는 도구.

### 학습 흐름 (D = 수업 당일)

| 시점 | 하는 일 | 매체 |
|---|---|---|
| **D+0** | 단원 지도 → 교과서 읽기 → 개념 카드 빈칸 → 자기 말로 → AI 진단 → 확인 3문항 | 앱 |
| **D+2** | 백지 지도 채우기 → 본 문제 풀이 | 종이 |
| **D+7** | 틀린 것만 재출제 → 한 장 정리 | 앱 + 종이 |

### 매체 배분 원칙

> **AI가 있어야만 되는 것만 앱에 넣는다.**

| 앱 | 종이 |
|---|---|
| 마인드맵(접었다 펴기) | 본 문제 풀이 |
| 자기 설명 → AI 진단 | 계산(합력·부력·무게) |
| 개념 카드 빈칸 | 그래프 읽기·그리기 |
| 확인 3문항(신호등) | **힘의 화살표 그리기** |
| 오답 리포트 | 백지 지도, 워크북 |

화면에서 객관식 누르는 건 **풀이가 아니라 찍기**입니다.
계산과 그리기는 손으로 해야 어디서 틀렸는지 남습니다.

## 2. 설계 원칙 (바꾸면 다른 물건이 됩니다)

### 2-1. 트리거 — 인출 단서의 일관성

개념마다 **질문 하나**가 붙고, 그 질문이 **세 군데에 똑같은 문장으로** 반복됩니다.

1. 마인드맵 노드
2. 개념 카드 제목 옆
3. D+2 백지 인출

학습할 때 쓴 단서와 시험 볼 때 쓸 단서를 **일부러 일치**시킨 것입니다.
질문을 매번 다르게 쓰면 효과가 사라집니다.

### 2-2. 하나의 문법 — "누가 · 누구에게 · 어느 쪽으로"

| 힘 | 누가 | 누구에게 | 어느 쪽으로 |
|---|---|---|---|
| 중력 | 지구가 | 물체를 | 지구 중심 쪽으로 |
| 탄성력 | 모양이 변한 물체가 | **변형시킨 물체에게** | 가해진 힘의 반대쪽으로 |
| 마찰력 | 맞닿은 면이 | 물체에게 | **미끄러지려는** 쪽의 반대로 |
| 부력 | 물이나 공기가 | 잠긴 물체를 | 위쪽으로 |

굵게 표시한 곳이 오개념이 가장 많이 생기는 자리입니다.

이 틀은 **끊어읽기에도 그대로** 씁니다. 교과서 문장을 "무엇이 / 무엇에 / 어떻게"로 끊으면
끊는 자리가 그대로 이 세 칸이 됩니다. **하나의 문법이 세 화면을 관통합니다.**

**사회 단원에도 같은 원리를 적용할 것.** 문법은 내용에 맞게 바꿉니다
(예: 지리 개념이면 "무엇을 기준으로 · 어느 방향으로 · 어디까지").

### 2-3. 접혀 있어야 한다

마인드맵 기본은 **접힌 상태**, 한 번에 한 갈래만 열림.
접혀 있어야 학생이 **예측**하고, 예측이 인출 시도가 되어 트리거로 작동합니다.
다 펼치면 마인드맵이 아니라 요약본입니다.

### 2-4. 되돌아오는 고리 (포섭)

낱개 지식은 상위 범주에 걸려야 이해가 됩니다("가젤은 영양이다").
교과서는 힘의 정의와 힘과 운동이 20쪽 넘게 떨어져 있어 학생이 낱말로 외웁니다.
→ 개념마다 맨 위 정의로 돌아가는 질문을 붙입니다.

**주의**: 종이 워크북에서는 이 고리를 뺐습니다. 앞뒤 맥락 없이 나오면 뜬금없습니다.
**화면에서만** 씁니다.

### 2-5. 4MAT 나선 배치

개념마다 4주기를 돌리면 24단계라 중1이 못 버팁니다.

| | 어디서 | 무엇 |
|---|---|---|
| Why | 단원 도입 **1회** | 경험 소환 → 뿌리 질문 |
| What | 개념마다 | 이름 + 크기·방향 |
| How | 개념마다 | 문제·화살표(종이) |
| If | 개념마다 짧게 + 단원 끝 크게 | 되돌아오는 고리 |

### 2-6. 개념어 유형별로 정리 양식이 다르다

| 유형 | 예 | 적어야 할 것 |
|---|---|---|
| 명칭 | 뉴턴(N), 용수철저울 | 이름 + 무엇을 재는지. 한 줄 |
| 성질 | 질량, 무게, 탄성 | 정의 + **무엇과 헷갈리는지**(나란히 비교) |
| 현상·원리 | 중력·탄성력·마찰력·부력 | 누가·누구에게·어느 쪽으로 + **예시** + **그림** |
| 과정 | 합력 구하기, 부력 구하기 | **순서**. 답이 아니라 단계 |

**현상·원리에만 그림 칸이 필요합니다.** 명칭에 그림 그리면 시간 낭비,
과정에 정의 쓰면 헛일입니다. 이걸 안 나누면 학생은 넷을 같은 방식으로 적고,
그게 "정리를 위한 정리"가 됩니다.

### 2-7. 예시는 명사가 아니라 문장으로

"고무줄"이 아니라 **"고무줄을 당겼다 → 늘어났다 → 손가락을 당긴다"**.
변화의 과정이 들어가야 이해가 되고 시험도 그렇게 나옵니다.

→ 예시 칸을 **세 칸으로 강제**:
`어떤 상황에서 → 무엇이 어떻게 되었나 → 그래서 힘은 어느 쪽으로`

명사 하나만 쓰고 넘어갈 수 없는 구조입니다.
예시는 **표 위에** 둡니다. 먼저 보여야 어떻게 쓰는지 압니다.

## 3. 디자인 시스템

### 3-1. 색

배경은 전부 **연하게**, 글자는 항상 **진한 먹색**.
워크북은 학생이 연필로 위에 쓰는 종이라 배경이 진하면 글씨가 안 보입니다.
**흰 글자로 뒤집지 않습니다.**

| 용도 | 값 |
|---|---|
| 본문 글자 | `#1A1A1A` |
| 선·테두리 | `#1A1A1A` (1.6~2px) |
| 소제목 배경 | `#CFEBD6` (연녹색) |
| 배지 | `#DFF0E4` + 테두리 `#A9CDB6` |
| 표 헤더·강조 칸 | `#FBF3DC` (크림) |
| 형광 강조 | `#FFF0A8` |
| 개념 농도 | `#F1F9F3` → `#E4F2E8` → `#D6EBDC` → `#C8E4D1` |

개념 이름 줄은 네 힘의 농도를 다르게 해서, 나란히 놓으면 순서가 느껴지게 합니다.
한 장만 보면 그냥 연한 녹색 띠입니다.

남는 공간은 아래에 몰지 말고 **섹션 사이 간격과 쓰는 칸 높이로 분배**합니다.

### 3-4. 하지 말 것

- **이모지 금지** — 인쇄용 PDF에서 흑백으로 깨집니다
- **기호(◇○▷) 금지** — 내용을 나타내지 않는 장식일 뿐입니다
- 소제목 배경색만으로 충분히 구분됩니다

### 3-5. 빈칸 스타일

빈 상자만 두면 쓸 때 지저분해집니다. **점선 밑줄**을 그어 둡니다
(`.ruled` 클래스, 11mm 간격).

### 3-6. 글쓰기 기준 (중요)

학생과 선생님이 읽는 모든 문장에 적용합니다.

**① 비문을 쓰지 않는다**
주어와 서술어가 맞아야 하고, 수식 관계가 헷갈리지 않아야 합니다.

**② 실제로 쓰는 말만 쓴다**
사전에는 있어도 사람들이 안 쓰는 말, AI가 자주 만들어 쓰는 어색한 표현을 피합니다.

실제로 나왔던 문제 사례:
- "어디서 갈렸나" → 아무도 안 쓰는 말. **"어느 부분이 헷갈렸나요?"** 로 고침
- "헷갈리는 짝" → **"헷갈리는 개념"**
- "무엇이 · 누구에게 · 어떻게" (제목으로) → **"나의 언어로 설명하기"**

**③ 애매하면 지어내지 말고 물어본다**
새 용어를 만들어야 할 것 같으면, 만들기 전에 확인을 받습니다.

**④ 라벨은 학생이 아는 말로**
내부 분류 용어와 학생에게 보이는 말을 구분합니다. (아래 12장 참조)

## 4. 확정된 단원 구조 (과학)

교과서 목차를 그대로 따르지 않고 **학생이 이해하기 쉬운 논리**로 재구성.

```
              힘 = 모양이나 운동 상태를 바꾸는 원인
                            │
        ┌───────────────────┼───────────────────┐
    무엇을 바꾸나        어떻게 다루나        어떤 것이 있나
        │                   │                   │
    ┌───┴───┐          ┌────┴────┐        ┌────┴────┐
   모양   운동상태     힘 하나   힘 여럿   안 닿아도   닿아야
     ┊       │            │        │         │         │
     ┊   ┌───┴───┐    ┌───┼───┐ ┌──┴──┐    중력    탄성력
     ┊  속력   방향   크기 방향 작용점 합력 평형          마찰력
     ┊                                                  부력
     └┈┈┈┈┈ 점선 관계: 모양이 변해야 탄성력이 생긴다 ┈┈┈┘
```

### 교과서와 다른 점 3가지

1. **'힘과 운동'을 뒤로 빼지 않고 ①에 합침** — 흩어진 내용을 모음
2. **평형을 '도구'로 묶음** — 평형은 힘의 종류가 아니라 다루는 방법
3. **네 힘을 접촉 여부로 가름** — 중력만 혼자인 이유가 구조로 보임
   - 단, **용어는 안 가르침**("안 닿아도 / 닿아야"로 풀어 씀).
     교과서에 없는 구분이라 시험 답안은 교과서 용어로 써야 하기 때문

### 조직도 규칙

**형제는 좌우로 나란히, 자식은 아래로.**
같은 층이 같은 높이에 있어야 형제 관계가 보입니다.
세로 목록(아코디언)은 위계가 안 보여서 마인드맵 역할을 못 합니다.

## 5. 산출물 현황

### 5-1. 앱 (`app/index.html`)

단일 HTML 한 벌 + 과목별 데이터 파일. 상단 과목 탭으로 전환합니다.
단계는 **가로 전환**, 지도 안에서는 세로 조망.

| 단계 | 내용 |
|---|---|
| 지도를 켜다 | 조직도, 한 번에 한 갈래만 펼침 |
| 개념을 읽다 | **빈칸으로 시작** → 교과서 미션 → 채운 뒤 정답 대조 + 한자 |
| 개념을 말하다 | 자기 설명 → AI 진단. **이전에 쓴 글이 있으면 위에 나란히 표시** |
| 개념을 확인하다 | 소단원 수만큼 (지금은 6문항) |

단계 이름은 **동사로 이어지는 흐름**입니다.
브랜드 '글로온'의 *생각을 켜다* 에서 1단계 '켜다'가 나옵니다.

### 5-2. 인쇄물 (`print/과목/`)

| 파일 | 장수 | 내용 |
|---|---|---|
| `○○_워크북.pdf` | 8~9 (세로) | **1장이 지도**, 그다음 개념/소단원 + 오답 + 한 장 정리 |
| `단원지도_채우기.pdf` | 1 (가로) | 지도만 따로 필요할 때 |
| `오답노트.pdf` | 1 | 한 문제에 한 장, 필요한 만큼 인쇄 |

**지도는 워크북 1장에 90도 눕혀 들어 있습니다.**
인쇄는 전부 세로 한 번으로 끝나고, 학생은 그 장만 종이를 시계 방향으로 돌려 씁니다.
지도를 세로로 다시 그리면 사회는 말단 칸이 10mm까지 줄어 손글씨가 어려워집니다.

```bash
python3 print/merge_map.py   # 가로 지도를 세로 페이지에 눕혀 워크북 앞에 붙임
```

`print/` 바로 아래에는 과목과 무관한 두 가지가 있습니다.

| 파일 | 용도 |
|---|---|
| `학부모_안내.pdf` | A4 1장. 학부모께 보여 드릴 때 |
| `다시봄_앱소개.pdf` | 가로 A4 14장. 화면으로 넘기며 설명할 때 (전화·줌) |

**PDF에 가로 페이지와 세로 페이지를 섞지 않습니다.** 인쇄가 번거로워집니다.
가로로 그린 것은 `merge_map.py` 로 세로 페이지 안에 눕혀 넣습니다.

### 5-3. 개념 정리 장 구성 (확정)

```
개념 정리  [현상과 원리]                  ← 배지는 제목 옆
──────────────────────────────────
[ 탄성력 — 무엇이·누구에게·어느 쪽으로? ]   ← 트리거는 이름 옆
  나의 언어로 설명하기
     누가 / 누구에게 / 어느 쪽으로 / 크기를 정하는 것
  일상생활의 예시로 설명하기
     예) …                              ← 예시가 표 위
     [어떤 상황에서 → 무엇이 어떻게 → 그래서 힘은]
  그림으로 나타내기
     (교과서 그림 따라 그리고 화살표 표시)
  궁금한 점                              ← 점선 5줄
```

**"궁금한 점"이지 "틀린 것"이 아닙니다.**
한 칸짜리 오답 표는 "하나만 써라"로 읽힙니다.
질문은 개수가 자유롭고, 질문을 만들려면 자기가 뭘 모르는지 알아야 해서 학습에 더 낫습니다.

### 5-4. 빌드 방법

```bash
python3 gen2.py      # 트리 HTML 생성 (연결선 포함)
python3 build2.py    # wb3.html, map.html, wrong2.html 생성
wkhtmltopdf --page-size A4 -T 15mm -B 15mm -L 15mm -R 15mm wb3.html 워크북.pdf
wkhtmltopdf --page-size A4 --orientation Landscape -T 14mm -B 14mm -L 14mm -R 14mm map.html 지도.pdf
```

지도 구조를 바꾸려면 `gen2.py`의 `TREE` 딕셔너리만 고치면 연결선까지 다시 그려집니다.
페이지별 칸 높이는 `build2.py`의
`.p-force` / `.p-pair` / `.p-wrong` / `.p-solo` / `.p-one` 클래스에서 조절합니다.

## 6. 주의사항

### 6-1. 질량을 중력 아래에 매달지 말 것

중력에서 갈라지는 것은 **무게**뿐. 질량은 물질의 양으로 독립 개념입니다.
마인드맵은 관계를 시각적으로 각인시키는 도구라, 구조가 틀리면
**오개념이 그림으로 박히고 텍스트보다 지우기가 훨씬 어렵습니다.**
이 단원 최대 오개념이 "질량=무게"입니다.

### 6-2. 저작권 — 교과서 표현을 쓰지 말 것

**보호됨**: 교과서 문장, 도입 질문, 삽화·사진, 탐구 수치, **소단원 구성 순서**
**자유로움**: 과학적 사실, 용어, 관계, 단위

마지막이 놓치기 쉽습니다. 개별 항목이 자유여도 **선택과 배열**은
편집저작물로 보호될 수 있습니다.

처리 방침:
- 뿌리를 교과서가 아니라 **교육과정 성취기준**에 둔다
  → 저작권과 타 출판사 호환이 동시에 해결됩니다
- **예시 사물을 반드시 갈아탄다** (교과서가 볼펜·겹친 책·빈 페트병을 쓰면 다른 것)
  - 회피일 뿐 아니라 **교육적으로 더 낫습니다**: 같은 예로 물으면 암기한 학생도
    맞히지만, 다른 예로 물으면 이해했는지가 드러납니다(전이 확인)
- **정의문은 요소 명세에서 새로 쓴다** — 교과서 문장을 조금씩 고치는 방식이 오히려 위험
- **쪽수를 넣지 않는다** — 출판사 전용이 되고, 학생이 직접 찾는 편이 학습에도 낫습니다
- 그림은 직접 그린 도식만, 탐구 수치는 비례만 유지하고 새로 생성

### 6-3. 진단 기준은 2층 — 교과서와 충돌 처리

교과서를 넘어서되 **교과서를 부정하지 않아야** 합니다.

실제 사례: 교과서는 마찰력 방향을 **"물체의 운동 방향과 반대"** 로 못박고 O/X까지 냅니다.
정확히는 "**미끄러지려는** 방향의 반대"(정지마찰력 포함)인데,
이대로 두면 **교과서대로 쓴 학생이 오개념 판정을 받습니다.**

| 층 | 하는 일 |
|---|---|
| 1층(채점) | 교육과정 수준에서 맞으면 **통과** |
| 2층(확장 메모) | 통과시킨 뒤 "그럼 비탈에 멈춰 있는 상자는?" 한 줄만 |

틀렸다고 하지 않고 다음 단계 씨앗만 심습니다.
탄성력의 작용 대상, 부력의 밀도도 같은 처리.

### 6-4. 한자는 선택적으로

**뜻을 실제로 열어주는 경우만.** 아니면 외울 것만 늘어납니다.

| 넣을 것 | 이유 |
|---|---|
| 浮力(뜰 부) | 방향이 글자에 있음 |
| 彈性(튈 탄) | 되돌아가는 성질이 보임 |
| 摩擦(문지를 마·비빌 찰) | 닿아야 한다는 조건이 글자에 |
| 平衡(저울대 형) | 힘이 없는 게 아니라 균형임을 보여줌 |

**重力은 단독으로 넣지 말 것.** 重을 "무거울 중"으로 풀면
**중력=무게 오개념을 앱이 직접 심습니다.**
→ **質量 · 重力을 나란히 대비**시키면 오히려 갈라주는 도구가 됩니다
("바탕의 양 vs 무거운 정도").

### 6-5. 비유 금지 — 특히 자석

"지구는 큰 자석 같다"는 중력 오개념 연구에서 반복 보고되는 위험 비유입니다.
자석은 특정 물질만 당기고, 극이 있고, **밀어내기도** 합니다.
→ 비유 대신 **반례 질문**. "깃털과 볼링공을 진공에서 놓으면?"

### 6-6. 자기 설명이 퀴즈보다 먼저

퀴즈 해설을 읽은 직후 "네 말로 설명해봐"를 하면
방금 읽은 문장을 재생할 뿐이고 **진단 데이터가 오염됩니다.**
→ **개념 → 자기 말로 → AI 진단 → 문제**

### 6-7. 문제는 읽은 직후에 많이 풀지 말 것

방금 본 문장이 작업기억에 떠 있어 **재인으로 풀리고** 학생은 "안다"고 착각합니다.
- D+0 앱 문항 = **신호등**(3문항, 채점용 아님)
- D+2 종이 문제 = 본 문제

### 6-8. 오개념을 앞세우지 말 것

오개념 목록을 그대로 보여주면 **틀린 문장을 읽는 셈**이라
오히려 각인됩니다(오정보 효과).
→ **오답지에 심어서 뒤에서 작동**시킵니다.

### 6-9. 과학에 키워드 추출을 시키지 말 것

키워드 추출은 **정보 위계**를 잡는 독서 기술, 과학은 **관계**를 잡아야 합니다.
"중력, 질량, 무게, N"만 뽑으면 관계가 날아가고 그 자리를 일상 직관이 채웁니다.
→ 대신 **용어 사냥**(정의되는 용어에만 동그라미).

### 6-10. 별도 노트 필기를 하지 않는다

앱의 "내 말로 설명하기"가 이미 노트의 인출 기능을 합니다.
추가하면 두 번째는 손이 지쳐서 베껴 쓰기가 됩니다.

| 도구 | 다루는 것 | 주기 |
|---|---|---|
| 교과서 표시 | 원문 위치 | 매 차시 |
| 워크북 | 개념 **사이의 관계** | 단원 1벌 |
| 개념어 앱 | 개념 **하나의 내부** | 용어별·상시 |

### 6-11. 개념어 앱은 안에 넣지 말고 옆에 둔다

주기가 다릅니다. 개념 이해는 단원 주기, 어휘는 매일 3분 누적.
단원 흐름 안에 박으면 간격 반복의 이점이 죽습니다.
→ 용어 사냥에서 표시한 단어가 **자동으로 앱 덱에 적립**.

### 6-12. 단권화는 하지 않는다

여러 출처를 모으는 작업인데 지금은 교과서 하나뿐이라 모을 게 없습니다.
대신 **한 장 정리** — 새로 쓰지 않고 앞에서 걸린 것만 옮깁니다.
분량이 적어야 실제로 봅니다.

## 7. 오답 피드백 기준 (확정)

같은 오답도 성격이 다릅니다. **세 층으로 나눠 판정합니다.**

| 구분 | 판정 조건 | 피드백 |
|---|---|---|
| **실수** | 같은 개념에서 **1회만** 틀림 | 아무것도 안 함. 정답만 확인하고 넘어감 |
| **오개념** | 같은 오답지를 **2회 이상** / 다른 문항에서 같은 오개념 | **반례 질문 하나.** 정답을 말해주지 않음 |
| **공백** | 자기 설명에 필수 요소가 아예 없음 | 개념 카드로 되돌림 |

### 개입 기준은 2회 (확정)

**1회는 건드리지 않습니다.** 중1이 한 번 틀릴 때마다 개입하면 피로해지고,
실제로 실수인 경우가 많습니다. **두 번째부터가 신호입니다.**

→ 코드에서는 `틀린횟수 >= 2` 일 때만 개입 로직이 발동합니다.

### 오개념 판정은 "무엇을 틀렸나"가 아니라 "무엇을 골랐나"로

오답지가 이미 오개념으로 설계돼 있으므로,
학생이 2번을 고르면 → "질량=무게 혼동"이 바로 나옵니다.
**문항이 곧 진단 도구**가 되는 구조입니다.

### 피드백 문장 규칙

1. 잘한 것을 먼저 말한다
2. **정답 문장을 그대로 주지 않는다**
3. 반례나 질문 하나로 끝낸다
4. **교과서 수준에서 맞으면 통과시킨다** (6-3의 2층 원칙과 동일)

## 8. 학습 기록 스키마 (확정)

### 원칙: 점수를 쌓지 않는다

몇 점인지는 아무것도 알려주지 않고 학생을 점수에 묶기만 합니다.
대신 **어디가 약한지**를 쌓습니다.

### 스키마

```
개념별 기록 (concept_id 기준)
  상태:      미학습 / 통과 / 부분 / 오개념
  자기설명:  [{날짜, 원문, 빠진요소[], 판정}]     ← 누적 저장
  오답:      [{날짜, 문항코드, 고른선택지, 오개념명}]
  틀린횟수:  n                                    ← 2 이상이면 개입
  궁금한점:  [{날짜, 내용}]
```

### 쌓는 이유

| 항목 | 왜 필요한가 |
|---|---|
| **개념별 상태** | 지도 위에 색으로 표시 → 어느 가지가 약한지 **구조로** 보임 |
| **자기 설명 원문** | 가장 값진 데이터. 이해가 어떻게 변했는지 보임 |
| **빠진 필수 요소** | "방향 빠짐"이 반복되면 그게 그 학생의 **패턴** |
| **오답 코드 + 고른 선택지** | 오개념 식별 |
| **틀린 횟수** | 1회 vs 2회 이상을 가르는 기준 |
| **날짜** | D+2, D+7 주기 관리 |
| **궁금한 점** | 학생이 스스로 만든 질문 = 메타인지 흔적 |

### 특히 중요한 두 가지

**① 자기 설명 원문은 반드시 남긴다**
현재 앱은 진단만 하고 버리고 있습니다. **이건 고쳐야 합니다.**
같은 개념을 D+7에 다시 쓰게 하고 **두 문장을 나란히** 보여주면
학생이 자기 성장을 직접 봅니다. 점수보다 훨씬 강한 동기가 됩니다.

> 저장이 압박이 되지 않게 하는 방법:
> 목록으로 쌓아 "네가 쓴 글 12개"라고 세지 말 것.
> **D+7에 나란히 놓는 용도로만** 꺼낼 것.

**② 빠진 요소의 패턴이 개별 오답보다 값지다**
"이 학생은 늘 방향을 빼먹는다"가 보이면
그건 개념 하나의 문제가 아니라 **읽기 습관**의 문제입니다.
→ 교과서 표시 단계에서 개입해야 하는 신호입니다.

## 9. 참고사항

### 9-1. 교과서가 이미 마인드맵을 시키고 있다

'스스로 확인하기' 옆 작은 트리 빈칸,
대단원 마무리의 생각 그물(가지 4개 + 핵심 단어).
우리 구조가 이 틀과 어긋나면 학생이 두 개를 따로 외웁니다.
**구조는 재구성하되 호환되는지 확인할 것.**

### 9-2. "크기와 방향"이 이 단원의 뼈대

네 힘의 학습목표가 전부 "크기와 방향을 설명할 수 있다"로 통일,
교과서 정리 트리도 전부 `크기 / 방향` 두 칸.
→ 힘마다 다른 질문 말고 **같은 두 질문**을 반복.
새 힘을 만나도 물을 것을 압니다.

### 9-3. 시험 빈출 (교과서 대단원 마무리 기준)

| 유형 | 어디에 |
|---|---|
| 힘의 3요소 / 단위 N | 앱 |
| **합력 계산**(같은 방향 +, 반대 −) | 종이 |
| 평형 조건 3가지(크기 같고, 방향 반대, **일직선상**) | 앱 |
| **질량 vs 무게 표 비교** | 앱 — 최다 빈출 |
| **용수철 길이 ∝ 탄성력** 그래프 | 종이 |
| 마찰력 크기 요인(거칠기·무게 / 부피 무관) | 앱 |
| 부력 = 공기 중 무게 − 물속 무게 | 종이 |
| **화살표 그리기 · 순서 나열** | 종이 |
| 나란한 힘 → 속력 변화 / 비스듬한 힘 → 둘 다 | 앱 |

문항 형식은 **⑤지선다**가 주력. (2지선다는 실제 시험과 너무 멉니다)

### 9-4. 오답 리포트 설계 (미착수)

3문항으로는 리포트가 안 나옵니다. 실수인지 오개념인지 구분이 안 됩니다.
→ **종이 채점 결과를 입력받는 구조**.
PDF 문항마다 코드를 붙이고(`과-중력-02`), 틀린 코드만 앱에 입력하면
해당 오개념 카드가 뜨고 노트에 쌓입니다.

리포트에 넣을 것:
- **개념별 상태** — 마인드맵 그림 위에 색으로(어느 가지가 약한지 구조로)
- **오개념 목록** — 반복된 것만(한 번은 실수)
- **다시 볼 것 3개** — 전부 나열하면 아무것도 안 합니다

### 9-5. 교과서 표시 규칙 3종 고정

규칙 없는 형광펜은 아무것도 아닙니다.
- 동그라미 = 정의되는 용어(→ 개념어 앱으로 적립)
- 밑줄 = 그 정의
- 화살표 = 인과·관계 서술

### 진단 기준 v1에서 고칠 6곳

1. 트리 구조에서 **질량이 중력 아래** → 분리

3. **13번 속력·속도 혼동** — 속도는 중1 교육과정 밖. 삭제
4. **5번 탄성력** — 필수 요소에 "**변형시킨 물체에게 작용한다**" 추가
5. **6번 마찰력** — 키워드 매칭이라 "운동 방향의 반대"가 통과함. 기준 좁힐 것
6. **힘의 효과 중 '모양 변화'** 가 통째로 빠져 있음

## 12. 과목 추가하는 법 (중요)

### 12-1. 화면 코드는 한 벌, 과목은 데이터만

```
app/
  _template.html      ← 화면 코드 원본. 과목이 늘어도 이 파일은 그대로
  data/
    science-force.js
    social-life.js
    (새 과목을 여기 추가)
  build_app.py        ← 템플릿 + 데이터를 합쳐 index.html 을 만듦
  index.html          ← 빌드 결과. 직접 고치지 말 것
```

새 과목은 `app/data/` 에 파일 하나를 넣고 아래를 실행하면 끝입니다.
스크립트가 `data/` 안의 모든 파일을 자동으로 찾아 합칩니다. 과목 탭도 자동으로 생깁니다.

```bash
cd app && python3 build_app.py
```

> **왜 합치나?**
> 브라우저에서 로컬 HTML 파일을 열거나 아티팩트 미리보기로 볼 때는
> `<script src="data/...">` 같은 외부 파일을 읽지 못합니다.
> 그래서 화면이 텅 빈 채로 뜹니다. 실제로 그 사고가 한 번 났습니다.
> 소스는 나눠 두고, 배포용 한 파일은 빌드로 만듭니다.
>
> **`index.html` 을 직접 고치면 다음 빌드에서 지워집니다.**
> 화면을 고칠 일이 있으면 `_template.html` 을 고치세요.

> **화면 파일을 복사해서 새 과목을 만들지 마세요.**
> 실제로 그렇게 했다가, 사회 앱에 과학의 "모양 ┈ 탄성력" 안내와
> "중력" 제목이 그대로 남는 일이 있었습니다.
> 복사본이 생기면 화면을 한 번 고칠 때마다 두 군데를 고쳐야 하고,
> 한쪽을 빠뜨리면 이런 잔재가 남습니다.

### 12-2. 두 가지 mode

개념 카드 구조가 과목마다 다릅니다. 데이터의 `mode` 값이 화면을 정합니다.

| mode | 개념 카드 구조 | 쓰는 곳 |
|---|---|---|
| `slots` | 고정 3칸 (누가·누구에게·어느 쪽으로) | 과학처럼 개념 하나가 한 장일 때 |
| `subs` | 소제목 N칸 | 사회처럼 소단원 하나가 한 장일 때 |

`slots` 는 각 칸에 `hl:true` 를 주면 채운 뒤 형광펜이 켜집니다.
**주어와 방향 두 곳만** 칠합니다. 많이 칠하면 아무것도 강조되지 않습니다.

### 12-3. 데이터 파일에 들어가는 것

```js
window.UNITS["과목-단원"] = {
  subject, unit, mode,
  tree:     { label, line, kids:[...] },     // 조직도
  relation: { text, showOn:[0,2] } | null,   // 트리로 못 그리는 관계
  concepts: [{ n, short, trigger, mission,
               slots|subs, size?, hanja?, hnote?, loop }],
  quiz:     [{ unit, why?, t, o:[{s, ok, w}] }]
};
```

`relation` 은 **과목마다 있을 수도 없을 수도** 있습니다.
과학은 "모양 ┈ 탄성력"이 있고 사회는 `null` 입니다.
없는 과목에 남겨 두면 다른 과목 안내가 뜹니다.

`showOn` 은 **어느 노드를 열었을 때 뜰지**를 지정합니다.

```js
showOn: [[0, 0], [2, 1]]   // [1층 index, 2층 index]
showOn: [[2]]              // 2층을 안 쓰면 그 갈래 전체에서 표시
```

관계와 상관없는 곳에서도 계속 떠 있으면 헷갈립니다.
**실제로 그 관계가 필요한 노드에만** 붙이세요.
예를 들어 "모양 ┈ 탄성력"은 `모양` 노드와 `닿아야`(탄성력이 있는 곳)에서만 뜹니다.

### 12-4. 추가한 뒤 반드시 검수

```bash
node check.js
```

이 스크립트가 자동으로 봅니다:

- 필수 항목 누락 (`trigger`, `loop`, 해설 등)
- 정답이 없거나 둘 이상인 문항
- 형광펜 표시가 하나도 없는 개념 (`slots` 모드)
- 까닭 쓰기 문항 개수 (0개면 부족, 3개 이상이면 과함)
- **다른 과목 용어가 섞였는지** ← 13-1의 사고를 막는 항목
- **교과서 쪽수가 들어갔는지** ← 6-2 출판사 중립 원칙

새 과목을 추가하면 `check.js` 의 `TERMS` 에 그 과목의 대표 용어도 등록해 주세요.

## 13. 앱 문항 만드는 기준

### 13-1. 소단원 하나에 한 문항

앱 문항은 **채점이 아니라 신호등**입니다.
어느 소단원이 흔들리는지만 보이면 됩니다.
12문항은 본 문제처럼 무거워지고, 3문항은 표본이 부족합니다.
→ **소단원 수만큼**. 지금은 과목마다 6문항입니다.

### 13-2. 오답지는 반드시 실제 오개념으로

**정답이 눈에 띄면 실패입니다.**

실제로 있었던 실패 사례:

> 역할 갈등에 대응하는 방법으로 알맞지 **않은** 것은?
> ④ 갈등이 사라질 때까지 아무 역할도 하지 않는다

개념을 몰라도 ④가 이상하다는 건 누구나 압니다. 이런 문항은 아무것도 진단하지 못합니다.

오답지는 **그 단원에서 학생이 실제로 하는 착각**이어야 합니다.

| 과목 | 대표 오개념 |
|---|---|
| 과학 | 질량=무게 / 평형=힘이 없음 / 힘의 방향=운동 방향 / 정지한 물체엔 마찰력 없음 / 움직이려면 힘이 계속 필요 |
| 사회 | 차이=차별 / 역할=역할 행동 / 사회화는 어린 시절만 / 자아 정체성은 혼자 만드는 것 / 갈등은 무조건 나쁜 것 |

### 13-3. 형식을 섞는다

객관식만 쓰지 않습니다. O/X, 사례 판단, 짝 맞추기, 빈칸을 섞습니다.
특히 사회는 **사례를 주고 무엇에 해당하는지 판단**하는 형식이 실제 시험과 가깝습니다.

### 13-4. 까닭 쓰기는 두 문항까지만

O/X나 판단형은 찍어도 절반이 맞습니다.
**까닭을 쓰게 하면 그게 안 됩니다.**

다만 전부 넣으면 지쳐서 대충 씁니다.
→ **찍기로 뚫리는 문항에만** 넣습니다. 데이터에서 `why:true` 로 표시합니다.
`check.js` 가 개수를 감시합니다.

## 15. 워크북 한 장 만들 때

### 15-1. 한 장에 들어가는 것 (두 과목 공통)

```
[과목] 정리   [성격 배지]
──────────────────────────────
[ 개념 또는 소단원 이름 — 트리거 질문 ]
  ① 나의 언어로 설명하기 / 소제목별로 정리하기
  ② 일상생활의 예시로 설명하기      ← 예시 문장이 표 위
  ③ 한자로 풀어 보기                ← 한 줄 띠
  ④ 그림으로 나타내기 (과학만)
  ⑤ 궁금한 점                       ← 점선
```

과학은 ①이 고정 3칸(누가·누구에게·어느 쪽으로), 사회는 **교과서 소제목이 그대로 칸**입니다.
사회에는 그림 칸이 없습니다 — 그릴 것이 없는 단원이라 억지로 넣지 않았습니다.

### 15-2. 한자는 한 줄 띠로

표로 넣으면 **한 장을 넘깁니다.** 실제로 넘쳐서 압축한 결과입니다.

```html
<div class="hjbar">
  <span class="hlab">한자로 풀어 보기</span>
  <b class="hc">浮</b> <span class="hm">뜰 부</span> + …
  <span class="hsep">—</span>
  <span class="hdesc">浮는 뜬다는 뜻이라 방향이 글자에 있습니다…</span>
</div>
```

**설명은 한 줄 안에 들어가게 짧게 씁니다.** 두 줄이 되면 페이지가 넘칩니다.
실제로 마찰력 설명이 길어서 한 장이 밀린 적이 있습니다.

한자가 뜻을 열어 주지 않는 개념은 **띠를 아예 넣지 않습니다**(6-4 참조).
사회의 ‘대처 방안’이 그런 경우인데, 그 장은 대신 궁금한 점을 한 줄 더 넣었습니다.

### 15-3. 여백 맞추는 순서

칸 높이를 바꾼 뒤에는 **반드시 다시 측정**합니다. 눈대중으로는 맞지 않습니다.

```python
im = convert_from_path("워크북.pdf", dpi=80)
# 각 장의 아래 여백(mm)을 출력해 16~25mm 안에 들어오는지 본다
```

- **장수가 늘어났다** → 어딘가 넘쳤습니다. 그 장을 이미지로 열어 무엇이 밀렸는지 봅니다
- **‘빈장’이 나온다** → 마지막 요소의 아래 여백이 페이지를 넘긴 것입니다
- **아래 여백이 40mm 넘는다** → 칸을 키웁니다
