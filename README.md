# 글로온 생각온

중학생이 일상·감정·끌림·독서·영화·뉴스·진로를 기록하고, AI와 **질문형 대화**를 나눈 뒤,
**자기 언어로 직접 글을 완성하는** 웹앱입니다.

AI가 글을 대신 써주는 앱이 아닙니다. AI는 학생이 이미 가지고 있는 경험과 감정을 질문으로
끌어내고, 대화에서 나온 재료를 **키워드와 글의 구조**로 정리해 줄 뿐입니다.

```
기록 → 대화 → 발견 → 구조화 → 직접 쓰기 → 돌아보기
```

## 이 앱이 지키는 것

- **AI는 완성된 글을 만들지 않는다.** 대화 종료 후 나오는 건 문단이 아니라 생각 설계 카드입니다.
- **학생이 말하지 않은 것을 지어내지 않는다.** 카드의 모든 항목은 학생이 실제로 한 말에서 나옵니다.
- **적성을 판정하지 않는다.** 관심 지도는 직업을 추천하지 않고, 반복해서 나타난 관심과
  해볼 수 있는 경험만 보여줍니다.
- **학생의 언어를 보존한다.** 맞춤법 교정은 학생이 눌렀을 때만, 원문을 지우지 않고 제안만 보여줍니다.
- **위험 신호가 보이면 멈춘다.** AI가 상담가 역할을 하지 않고, 신뢰할 수 있는 어른과 전문 기관을 안내합니다.

이 원칙은 프롬프트에만 적어둔 것이 아니라 코드에 장치로 들어가 있습니다.

| 장치 | 위치 |
| --- | --- |
| 답변을 문장 3개·질문 1개로 잘라냄 | `shared/coach.js` `enforceOneQuestion()` |
| 카드 항목 120자 제한 (문단화 방지) | `shared/thinkingCard.js` |
| 빈칸(`___`) 없는 문장 시작점은 폐기 | `shared/thinkingCard.js` |
| 원문에 없는 교정 제안은 폐기 | `shared/proofread.js` |
| 위험 표현 감지 시 저장·전송 중단 | `src/lib/safety.js` |

## 기술 구성

- React 18 + Vite + Tailwind CSS (모바일 우선, 데스크톱은 사이드바 + 넓은 글쓰기 화면)
- 해시 라우팅 — Vercel·Netlify 어디에 올려도 새로고침이 깨지지 않습니다
- AI 호출은 서버리스 함수에서만. **API 키는 서버 환경변수에만 두고 클라이언트로 내려보내지 않습니다**
- 서버 로직은 `shared/` 에 한 벌만 두고 Vercel(`api/`)과 Netlify(`netlify/functions/`)가 함께 씁니다

```
src/lib/       types · store(데이터) · ai · safety · fallback · insights
src/screens/   Auth Home Collect NewEntry EntryDetail Chat CardView Write Library InterestMap Settings
src/components/ 공통 UI · 사이드바/하단탭 · 생각 카드 · 안전 안내
shared/        프롬프트 + 카드 JSON 검증기 + 세 개의 핸들러 (서버 전용)
api/           Vercel 서버리스 함수 (coach · card · proofread)
netlify/functions/ 같은 핸들러의 Netlify 래퍼
```

### 데이터 저장 — 지금은 '로컬 모드'

기획서 15절의 Firestore 컬렉션 구조(`users` / `entries` / `conversations` / `thinkingCards` /
`drafts`)를 그대로 따르되, **지금 백엔드는 브라우저 `localStorage`** 입니다.

- 모든 문서에 `ownerId` 가 있고, 읽기/쓰기마다 로그인한 사용자와 대조합니다.
  다른 계정의 문서는 조회 자체가 되지 않습니다.
- **다만 이건 서버 인증이 아닙니다.** 기록은 그 기기의 브라우저 안에만 있고, 다른 기기에서는
  보이지 않으며, 브라우저 데이터를 지우면 함께 사라집니다. 4자리 비밀번호는 같은 기기를 쓰는
  사람이 실수로 열어보는 것을 막는 정도입니다. 앱 안에서도 이 사실을 학생에게 그대로 알립니다.

**Firebase 로 전환하기**: 화면 코드는 `src/lib/store.js` 가 내보내는 함수들만 사용합니다.
Firebase Auth + Firestore 로 바꾸려면 이 파일의 구현만 교체하고, 아래 규칙을 함께 배포하면 됩니다.

```js
// firestore.rules 초안
match /{collection}/{docId} {
  allow read, update, delete: if request.auth != null
    && resource.data.ownerId == request.auth.uid;
  allow create: if request.auth != null
    && request.resource.data.ownerId == request.auth.uid;
}
```

## 실행

```bash
npm install
npm run dev      # 개발 서버 (http://localhost:5173)
npm run build    # 프로덕션 빌드 → dist/
npm run preview  # 빌드 결과 미리보기
```

`npm run dev` 는 정적 화면만 띄우므로 `/api/*` 는 404 가 됩니다. 이때 앱은 오류를 내지 않고
**질문 은행으로 대화를 이어가고, 생각 카드도 학생이 쓴 문장에서 직접 만듭니다.**
서버리스 함수까지 로컬에서 돌리려면 `vercel dev` 또는 `netlify dev` 를 쓰세요.

## 배포

Vercel과 Netlify 어느 쪽이든 됩니다.

**Vercel** — 저장소를 연결하면 Vite 프로젝트로 인식합니다. `api/` 폴더가 자동으로 서버리스 함수가 됩니다.

**Netlify** — `netlify.toml` 에 빌드·함수·리다이렉트 설정이 들어 있습니다.
`/api/*` 요청이 함수로 이어집니다.

### AI 기능 켜기

두 플랫폼 모두 환경변수 하나만 있으면 됩니다.

```
ANTHROPIC_API_KEY = sk-ant-...
ANTHROPIC_MODEL   = claude-opus-5   (선택, 기본값이 claude-opus-5)
```

키가 없어도 앱은 정상 동작합니다(우아한 열화). 대신 질문이 준비된 질문 은행에서 나오고,
맞춤법 확인만 쓸 수 없습니다.

## 확인한 것 / 확인하지 못한 것

**확인함** — 실제 브라우저로 가입 → 기록 → 대화 → 대화 마치기 → 생각 카드 → 글쓰기 →
자동 저장 → 새로고침 후 유지 → 관심 지도 → 보관함까지 전 과정을 돌렸고, 모바일·데스크톱
레이아웃과 서버 핸들러 가드(키 없음 503, 잘못된 요청 400/413, 카드 스키마 검증) 11건을 통과했습니다.

**확인 못 함** — 이 환경에 `ANTHROPIC_API_KEY` 가 없어 **Claude API 실호출 경로는 검증하지
못했습니다.** 배포 후 환경변수를 넣고 대화를 한 번 돌려 확인해 주세요.
