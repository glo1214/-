# PROJECT_MASTER — 교과 학습 스케줄러

> 이 문서는 교과 학습 스케줄러 프로젝트의 유일한 기준 문서다.  
> 별도의 `DECISIONS.md`를 만들지 않고, 확정 사항·미결정 사항·현재 상태·변경 기록을 이 문서 안에서 함께 관리한다.

## 0. AI 작업 규칙

Claude, ChatGPT 등 이 프로젝트를 다루는 AI는 다음 규칙을 따른다.

1. 작업을 시작하기 전에 이 문서를 먼저 읽는다.
2. 먼저 현재 코드와 구현 상태를 분석하고, 곧바로 수정하지 않는다.
3. 분석 결과를 아래 세 항목으로 구분해 제시한다.
   - 현재 상태
   - 제안하는 수정 사항
   - 이번 작업에서 건드리지 않을 사항
4. 사용자가 승인한 내용만 코드와 이 문서에 반영한다.
5. 확정된 방향을 임의로 바꾸거나 새로운 기능을 추가하지 않는다.
6. 결정이 바뀌면 본문의 최신 기준을 먼저 수정하고, 맨 아래 변경 기록에 날짜와 이유를 한 줄 남긴다.
7. 스케줄 생성 로직과 화면 UI를 분리해 기존 학습 앱에 나중에 붙일 수 있게 한다.
8. 교과서·자습서·문제집 사진은 개념과 교육과정 범위를 확인하는 참고 자료로만 사용한다. 원문의 문장·삽화·문제·선택지·편집 구성을 복제하지 않는다.
9. 과학 개념의 정의·조건·방향·원인과 결과를 임의로 추론하지 않는다. 이 문서의 진단 기준과 사용자가 제공한 교재 범위를 대조한 뒤 작성한다.
10. 자료끼리 표현이 다르거나 과학적 판단이 애매하면, AI가 한쪽을 임의로 선택하지 않고 **충돌 지점과 선택지를 사용자에게 질문한다.**
11. 확인되지 않은 내용을 그럴듯하게 채워 넣지 않는다. 검토가 필요한 내용은 `미확정`으로 남기고 코드 반영을 멈춘다.

## 1. 목적

학교 수업 진도를 기준으로 학생의 **예습·당일 복습·간격 반복 복습**을 자동 배치하는 웹 스케줄러를 만든다.

이 도구의 핵심 목표는 단순한 일정 관리가 아니라 다음 학습 활동이 자동으로 일정에 반영되게 하는 것이다.

- 학교에서 배운 내용을 **당일에 정확히 복습**
- 잊기 전에 **여러 차례 간격 반복 복습**
- 아직 배우지 않은 내용은 **짧게 예습**
- 오개념이 있는 개념은 **교과서·AI·문제집을 함께 활용해 교정**
- 서술형 문제를 위해 **자기 말로 설명하고 쓰는 연습**

### 1-1. 이 앱이 해결하려는 핵심 학습 문제

학생의 어려움은 단순히 개념을 모르는 데서 끝나지 않는다. 학생은 낯선 교과 개념어를 자신이 이미 아는 익숙한 뜻에 잘못 연결하기도 한다. 이렇게 한 번 형성된 연결은 정답이나 피드백을 여러 번 보아도 쉽게 바뀌지 않는다.

실제 사례로, 해당 교과서 지문에서 ‘일반화’가 여러 사례를 상위 개념으로 묶는 사고를 뜻하는데도 학생이 이를 ‘다수결의 원칙’으로 이해할 수 있다. 학생은 단어를 전혀 모르는 것이 아니라 **다른 개념을 그 단어에 붙여 놓은 상태**다.

이 상태에서는 다음 문제가 나타난다.

- 교과서 문장을 읽어도 자신이 원래 알고 있던 뜻으로 해석한다.
- 정답을 확인한 직후에는 맞히지만 새로운 사례에서는 다시 틀린다.
- 자기 말로는 설명하지만 교과 개념의 기준·조건·관계가 빠진다.
- 서술형 피드백을 받아도 문장만 고칠 뿐 개념 연결은 바뀌지 않는다.
- 일상어의 뜻과 교과 개념어의 뜻을 구분하지 못한다.

따라서 이 앱은 단순히 설명을 더 많이 제공하는 것이 아니라, 학생이 가진 기존 생각을 드러내고 교과 개념과의 차이를 확인한 뒤 **개념의 경계와 관계를 다시 구성하도록 돕는 것**을 핵심 문제로 삼는다.

### 1-2. 교육 철학

- 학습은 정답 문장을 받아 적는 일이 아니라 **개념 사이의 연결이 바뀌는 과정**이다.
- 학생의 자기 설명은 완성된 답이 아니라, 현재 어떤 개념 구조를 가지고 있는지 보여 주는 **진단 자료**다.
- 오개념은 틀렸다고 알려 주는 것만으로 바뀌지 않는다. 자기 생각과 교과 개념을 비교하고, 반례·비예시·새로운 사례를 통해 기존 연결이 성립하지 않는 이유를 확인해야 한다.
- 자기 언어와 교과 언어 중 하나를 선택하게 하지 않는다. **자기 말 → 필수 개념과 관계 확인 → 정확한 교과 문장**으로 연결한다.
- 개념을 이해했다는 것은 정의를 읽었다는 뜻이 아니라, 개념의 기준과 경계를 알고 새로운 사례에 적용하며 설명할 수 있다는 뜻이다.
- AI는 정답을 대신 써 주는 도구가 아니라, 학생의 설명에서 잘못 연결된 개념과 빠진 관계를 찾아 다시 생각하게 하는 도구다.

### 1-3. 교육 목표

학생이 다음을 할 수 있게 한다.

1. 현상·사례와 교과 개념어를 정확하게 연결한다.
2. 자신의 기존 생각과 교과 개념의 차이를 발견한다.
3. 개념의 정의뿐 아니라 기준·조건·관계·결과를 이해한다.
4. 예시와 비예시를 구분하고 새로운 사례에 개념을 적용한다.
5. 자기 말로 설명한 뒤 필수 개념어를 사용해 정확한 교과 문장으로 다시 표현한다.
6. 시간이 지난 뒤에도 답을 보지 않고 개념과 관계를 인출한다.

## 2. 학습 원리

### 2-1. 기본 학습 흐름

학생이 실제로 수행하는 당일 개념 학습은 다음 6단계를 기본으로 한다.

**만남 → 인지 → 이해 → 오개념 비교·교정 → 적용 → 표현·즉시 인출**

- **만남**: 현상·그림·사례를 처음 접한다.
- **인지**: 현상과 교과 개념어를 연결한다.
- **이해**: 정의, 조건, 관계, 결과를 구조적으로 이해한다.
- **오개념 비교·교정**: 자신이 원래 알던 것과 교과 개념을 비교하고, 반례나 비예시를 통해 기존 연결을 수정한다.
- **적용**: 다른 사례나 조건에서도 같은 개념인지 판단하고 이유를 설명한다.
- **표현·즉시 인출**: 교과서를 덮고 자신의 말로 설명한 뒤 필수 개념어를 사용해 다시 표현한다.

6단계를 마친 뒤 소량의 문제를 풀어 이해를 검증한다. 문제는 학습의 시작이나 6단계 안의 개념 형성 활동이 아니라, 어느 단계가 무너졌는지 확인하는 최종 도구다.

문제를 풀기 전에 먼저 책을 덮고 설명한다. 문제의 선택지와 해설을 먼저 보면, 학생이 자신의 개념을 꺼내는 대신 방금 본 문장을 재생할 수 있기 때문이다.

며칠 뒤에는 스케줄러가 같은 개념을 다시 불러와 **지연 인출**을 진행한다. 따라서 인출은 두 번 작동한다.

- **즉시 인출**: 당일, 교과서를 덮고 설명하기
- **지연 인출**: 며칠 뒤, 자료 없이 다시 설명하고 적용하기

학생 화면에서는 다음 6개 행동으로 제시한다.

> **① 장면 보기 → ② 개념 이름 붙이기 → ③ 개념 구조 잡기 → ④ 내가 알던 것과 비교하기 → ⑤ 다른 사례에 적용하기 → ⑥ 책 덮고 말하고 쓰기**

학생이 짧게 기억할 때는 다음 문구를 사용한다.

> **보고 → 연결하고 → 이해하고 → 확인하고 → 설명하고 → 풀기**

여기서 마지막 ‘풀기’는 개념 형성 6단계가 끝난 뒤 이어지는 문제 검증을 뜻한다.

### 2-2. 학교 수업과 복습의 관계

학교 수업을 학습의 기준점으로 둔다.

- **수업 전**: 만남까지만 하는 짧은 예습
- **학교 수업**: 개념의 인지와 1차 이해
- **수업 당일**: 정확한 이해, 오개념 교정, 표현과 즉시 인출
- **문제집**: 자기 설명 이후 소량의 문제로 적용·검증
- **이후**: 간격 반복을 통한 지연 인출

학교 진도를 앞서서 깊게 공부하기보다, 아직 배우지 않은 부분은 **낯설지 않을 정도의 짧은 예습**만 한다.

| 시점 | 학습 단계 | 기본 활동 |
| --- | --- | --- |
| 수업 전 | 만남 | 제목·그림·표·실험·굵은 글씨를 보고 질문 하나 남기기 |
| 학교 수업 | 인지·1차 이해 | 현상과 개념어 연결, 선생님의 설명과 실험을 통해 첫 구조 만들기 |
| 수업 당일 | 정확한 이해·오개념 교정 | 교과서로 정의와 관계를 확인하고, 기존 생각과 다른 부분 점검하기 |
| 새로운 사례 | 적용 | 같은 개념인지 판단하고 그 이유 설명하기 |
| 책을 덮은 뒤 | 표현·즉시 인출 | “이게 뭐야? 왜 그래? 예를 들어봐.”에 답하고 한 문장 쓰기 |
| 그다음 | 문제·검증 | 문제집 5~10문제를 풀고 오류 원인 분류하기 |
| 며칠 뒤 | 지연 인출 | 자료 없이 핵심 개념과 관계를 다시 설명하고 취약 문제 재도전하기 |

예습에서는 정의 암기, 문제집 선행, AI를 통한 깊은 설명을 기본 활동으로 넣지 않는다. 학생이 자기식 해석을 먼저 굳히지 않도록 학교 수업에서 첫 개념 구조를 잡을 기회를 남겨 둔다.

당일 복습은 학생 상황에 따라 20~30분 안에서 조정한다.

- 오늘 배운 범위 확인: 1~2분
- 교과서 읽기와 개념 구조 확인: 약 10분
- 막힌 부분 AI 질문과 오개념 비교: 최대 5분
- 책을 덮고 말하기·한 문장 쓰기: 약 5분
- 문제집 소량 풀이와 오류 분류: 약 5~10분

### 2-3. 자기 설명과 개념어 설명의 관계

자기 설명과 개념어 설명은 같은 것이 아니다.

| 구분 | 목적 | 확인할 내용 |
| --- | --- | --- |
| 학습 전 자기 설명 | 현재 학생의 개념 연결을 드러내는 진단 | 학생이 그 단어를 어떤 뜻과 사례에 연결하고 있는가 |
| 학습 중 비교·교정 | 자기 생각과 교과 개념의 차이를 확인 | 기준·조건·관계·예시·비예시 중 무엇이 다른가 |
| 학습 후 개념어 설명 | 바뀐 이해를 교과 언어로 재구성 | 필수 개념어와 관계를 사용해 정확히 설명하는가 |
| 이후 인출 | 수정된 개념 연결이 유지되는지 확인 | 자료 없이 다시 설명하고 적용할 수 있는가 |

따라서 자기 설명을 완전히 없애지 않는다. 다만 모든 개념에서 같은 긴 서술을 반복하지 않고, **학습 전에는 기존 생각을 짧게 드러내고 학습 후에는 바뀐 개념 연결을 확인하는 방식**으로 사용한다. 단원 또는 수업 범위 전체에 대한 긴 자기 설명은 복습 흐름의 마지막에 한 번 배치한다.

AI 피드백은 학생 문장을 곧바로 모범 답안으로 고쳐 주지 않는다. 먼저 다음 순서로 작동한다.

1. 학생이 연결한 의미와 사례를 파악한다.
2. 교과 개념과 다른 지점을 구체적으로 표시한다.
3. 반례·비예시·비교 질문 중 하나를 제시한다.
4. 학생이 다시 판단하거나 설명하게 한다.
5. 마지막에 필수 개념어와 관계를 확인한다.

### 2-4. 가젤 스토리

가젤 스토리는 학생이 하나의 개념을 알게 되는 과정을 가젤을 처음 만나는 과정에 빗댄 학습 모델이다. 개념 학습은 7단계이며, 그 뒤에 문제 검증이 이어진다.

1. **만남**: 가젤의 모습을 먼저 보듯 현상·장면·사례를 본다.
2. **인지**: “저 동물이 가젤이구나”라고 이름을 붙이듯 현상과 개념어를 연결한다.
3. **이해**: 가젤의 분류·특징·서식 환경을 알듯 개념의 정의·조건·관계·결과를 구조화한다.
4. **오개념 비교·교정**: 자신이 알던 것과 교과 개념을 비교하고 반례나 비예시로 기존 연결의 한계를 확인한다.
5. **적용**: 새로운 장면에서도 같은 개념인지 판단하고 이유를 설명한다. 이 단계는 문제집 풀이가 아니라 짧은 사례 판단이다.
6. **표현**: 자기 말로 설명한 뒤 필수 개념어를 확인하고 정확한 교과 문장으로 다시 쓴다.
7. **즉시 인출**: 자료를 덮고 “이게 뭐야? 왜 그래? 예를 들어봐.”에 답한다.

가젤 스토리의 개념 학습이 끝난 뒤 **문제·검증**을 진행한다. 문제를 틀리면 정답만 고치지 않고 무너진 학습 단계로 돌아간다.

문제 오류는 다음처럼 이전 단계와 연결해 진단한다.

| 오류 모습 | 돌아갈 단계 |
| --- | --- |
| 개념어 자체를 모르거나 현상과 이름을 연결하지 못함 | 인지 |
| 정의는 알지만 조건·관계·결과를 빠뜨림 | 이해 |
| 자신의 기존 직관을 그대로 적용함 | 오개념 비교·교정 |
| 개념은 알지만 새로운 사례에 사용하지 못함 | 적용 |
| 알고 있지만 말이나 글로 정확히 설명하지 못함 | 표현 |

#### Why → What → How → If와의 관계

`Why → What → How → If`는 화면을 네 개로 고정하는 순서가 아니라, 전체 수업 설계에서 네 기능이 빠지지 않았는지 확인하는 거시 프레임으로 사용한다.

| 거시 프레임 | 가젤 스토리에서의 역할 |
| --- | --- |
| Why | 현상·질문·왜 배워야 하는지 확인하기 |
| What | 개념 인지 → 정의 → 구조 이해 |
| How | 사례 적용 → 문제 해결 → 서술 |
| If | 다른 조건·새로운 상황·변형 문제에서 전이 확인 |

가젤 스토리는 이 거시 프레임 안을 **만남 → 인지 → 이해 → 오개념 비교·교정 → 적용 → 자기 설명 → 인출**로 더 촘촘하게 나눈다.

### 2-5. 오개념 진단 원리

단원별 진단 기준은 반드시 필요하다. AI가 학생의 설명을 일반적인 문장력이나 키워드 개수로만 평가하지 않고, **해당 개념의 필수 관계와 대표 오개념**을 기준으로 판단하게 하기 때문이다.

진단은 다음 순서로 한다.

1. **필수 요소 확인**: 정의·조건·관계·결과 중 빠진 것이 있는가.
2. **개념 경계 확인**: 예시와 비예시를 구분하는가.
3. **관계 정확성 확인**: 개념어는 들어갔지만 원인·대상·방향·조건을 잘못 연결하지 않았는가.
4. **오개념 후보 확인**: 대표 오개념과 같은 판단이 나타나는가.
5. **반복 증거 확인**: 한 번의 실수인지, 다른 문항이나 설명에서도 같은 연결이 반복되는지 확인한다.
6. **전이 확인**: 새로운 사례에서도 수정된 개념을 적용하는가.
7. **표현 확인**: 자기 말에서 필수 개념어를 사용한 교과 문장으로 이동할 수 있는가.

진단 결과는 다음을 구분한다.

| 상태 | 의미 | 기본 개입 |
| --- | --- | --- |
| 공백 | 필수 요소가 설명에 없음 | 해당 개념 카드로 돌아가기 |
| 부분 이해 | 일부 요소는 있으나 관계나 조건이 빠짐 | 빠진 관계를 찾는 질문 제공 |
| 오개념 후보 | 대표 오개념과 같은 판단이 한 번 나타남 | 정답을 주지 않고 반례 질문 제공 |
| 오개념 확인 | 다른 문항·설명에서도 같은 잘못된 연결이 반복됨 | 비교 활동과 새 사례 적용 다시 진행 |
| 표현 문제 | 이해와 적용은 되지만 문장으로 구성하지 못함 | 자기 말 → 핵심어 → 교과 문장 순서 제공 |

한 번 틀렸다는 이유만으로 곧바로 오개념으로 확정하지 않는다. 같은 잘못된 연결이 두 번 이상 나타나거나, 사전 설명에서 안정적으로 드러났을 때 오개념으로 확인한다.

AI 채점은 두 층으로 운영한다.

- **1층 — 교육과정 기준**: 교과서 수준에서 맞으면 통과시킨다.
- **2층 — 확장 질문**: 통과시킨 뒤 더 정확한 개념이 필요한 경우 질문이나 반례를 한 줄 제시한다.

단원별 상세 기준도 이 문서 맨 아래의 부록에 둔다. 단원 수가 늘어나더라도 별도 기준 문서를 만들지 않고 `부록 A`, `부록 B`처럼 이어서 추가한다.

### 2-6. 위계형 질문–답 개념 지도

이 앱의 개념 지도는 중심 단어에서 사방으로 가지를 펼치는 일반적인 방사형 마인드맵이 아니다. **상위 개념을 위에 두고, 하위 개념을 아래로 내려가며 배치하는 위계형 개념 지도**를 사용한다. 가지의 깊이는 정보의 우선순위와 포함 관계를 나타낸다.

개념 지도는 다음 두 가지 보기를 같은 데이터로 제공한다.

| 보기 | 목적 | 표현 방식 |
| --- | --- | --- |
| 구조 지도 | 단원 전체에서 각 개념의 위치와 상하 관계를 파악 | 상위 개념 → 중간 개념 → 세부 개념을 명사형으로 배치 |
| 질문–답 설명 지도 | 각 가지의 의미를 학생이 직접 설명하고 인출 | 질문을 상위 노드에 두고, 답과 근거를 하위 노드로 배치 |

두 보기는 별개의 학습 내용이 아니다. **구조 지도에서 본 관계를 질문–답 형태로 다시 꺼내 설명하게 하는 한 가지 학습 구조**다. 구조 지도는 “어디에 속하는가”를 보여 주고, 질문–답 설명 지도는 “그 관계를 말로 설명할 수 있는가”를 확인한다.

#### 배치 원칙

1. 단원의 가장 큰 개념을 맨 위에 둔다.
2. 같은 수준의 개념은 같은 높이에 나란히 둔다.
3. 하위 개념은 반드시 관련 상위 개념의 아래에 둔다.
4. 중요한 핵심 관계일수록 위쪽에, 세부 조건과 예시는 아래쪽에 둔다.
5. 선은 단순 연상이 아니라 **포함·종류·원인·결과·표현 방법** 같은 관계를 나타낸다.
6. 예시는 핵심 개념과 같은 수준에 두지 않고, 해당 개념 아래의 말단 가지로 둔다.
7. 전체 지도를 먼저 본 뒤, 현재 배우는 가지를 확대해 학습한다.
8. 질문 노드는 이후 자기 설명과 간격 반복 복습에서 그대로 인출 질문으로 재사용한다.

#### 「힘」 단원의 구조 지도 예시

- **힘**
  - **힘의 기본 구조**
    - 힘이란 무엇인가
    - 힘의 효과
      - 모양의 변화
      - 운동 상태의 변화
        - 빠르기의 변화
        - 운동 방향의 변화
    - 힘의 표시
      - 힘의 크기
      - 힘의 방향
      - 힘의 작용점
  - **여러 힘이 함께 작용할 때**
    - 합력
    - 힘의 평형
  - **힘의 종류**
    - 중력
    - 탄성력
    - 마찰력
    - 부력

#### 「힘」 단원의 질문–답 설명 지도 예시

| 핵심 질문 | 학생이 연결해야 할 답 | 아래로 이어질 세부 가지 |
| --- | --- | --- |
| 힘이란 무엇인가? | 물체의 모양이나 운동 상태를 변화시키는 원인이다. | 모양의 변화, 빠르기의 변화, 운동 방향의 변화 |
| 힘은 물체에 어떤 영향을 주는가? | 물체의 모양 또는 운동 상태를 바꿀 수 있다. | 모양, 빠르기, 운동 방향 |
| 힘은 어떻게 표시하는가? | 힘의 크기·방향·작용점을 화살표로 나타낸다. | 크기=화살표의 길이, 방향=화살표가 향하는 방향, 작용점=화살표의 시작점 |
| 여러 힘이 함께 작용하면 어떻게 판단하는가? | 여러 힘과 같은 효과를 내는 합력을 구하고, 합력이 0인지 확인한다. | 합력, 힘의 평형 |
| 힘에는 어떤 종류가 있는가? | 작용 조건과 방향이 다른 여러 힘이 있다. | 중력, 탄성력, 마찰력, 부력 |

질문은 단순한 제목이 아니라 학생이 답해야 할 **설명 과제**다. 학생이 질문에 자기 말로 먼저 답한 뒤, 지도에서 빠진 핵심 관계를 확인하고 교과 언어로 다시 설명한다. 따라서 이 지도는 가젤 스토리의 `이해` 단계에서 구조를 만들고, `표현·인출` 단계에서 같은 구조를 꺼내 쓰도록 연결한다.

## 3. 사용 자료의 역할

### 교과서

학습의 중심 자료다.

- 학교 진도 확인
- 정의와 핵심 개념 확인
- 그림·표·실험 확인
- 개념 구조 이해
- 복습 기준점

### AI

모르는 내용과 오개념을 해결하는 보조 도구다.

- 이해되지 않는 교과서 설명 질문
- 직관적 생각과 과학 개념의 차이 설명
- 학생이 개념어를 엉뚱한 기존 개념에 연결했는지 확인
- 예시와 비예시를 통해 개념의 경계 확인
- 반례 질문을 통해 기존 오개념을 다시 판단하게 하기
- 예시 요청
- 서술형 답안의 개념적 정확성 확인
- 자기 설명에서 빠진 개념 확인

AI가 교과서보다 앞서는 주 학습 자료가 되지 않도록 한다.

### 문제집

학습 후 검증 도구다.

- 개념 적용
- 서술형 문제 연습
- 오개념 확인
- 이해 단계의 결손 발견

문제를 틀렸을 때는 단순히 정답을 고치는 것이 아니라 아래 중 원인을 확인한다.

- 인지 문제
- 이해 문제
- 오개념 문제
- 적용 문제
- 표현 문제

## 5. 기본 스케줄 생성 원칙

- 질문 하나 만들기

## 6. 간격 반복 복습

한 번 학습한 핵심 내용은 당일 복습 이후 약 5회 반복한다.

기본 간격 예시:

- 0회차: 수업 당일
- 1회차: +2일
- 2회차: +5일
- 3회차: +8일
- 4회차: +12일
- 5회차: +18일

학생 일정상 정확한 날짜에 복습하기 어렵다면 **±1~2일 범위에서 자동 조정**할 수 있다.

사용자가 복습 간격 프리셋을 변경할 수 있게 한다.

```json
[2, 5, 8, 12, 18]
```

## 16. 개발 원칙

- 기존 학습 앱에 나중에 붙이기 쉽도록 만든다.
- 스케줄 생성 로직과 UI를 분리한다.
- 데이터 구조를 단순하게 유지한다.
- 일정 생성 규칙은 하드코딩하지 않고 설정값으로 둔다.
- 예습과 복습을 명확히 구분한다.
- 학교 진도가 전체 시스템의 기준이 된다.
- 문제집은 학습 시작점이 아니라 검증 도구로 사용한다.
- 반복 복습은 단순 재독보다 인출과 설명 비중을 점차 높인다.
- 교과서·자습서·문제집에서는 저작권의 대상이 아닌 사실·개념·원리와 학습 요소만 추출한다.
- 앱의 설명 문장·질문·선택지·사례는 교육 목표와 오개념 진단 기준을 바탕으로 처음부터 새로 작성한다. 단어 몇 개만 바꾸는 방식으로 원문을 변형하지 않는다.
- 화살표 도식과 개념 그림은 자체 HTML·CSS·SVG 또는 새로 제작한 이미지로 구성한다. 참고 교재의 인물·사물 배치, 구도, 색, 단계 구성과 실질적으로 유사하게 만들지 않는다.
- 교재 사진·삽화·쪽수·출판사 고유 표현은 앱과 배포 파일에 넣지 않는다.
- 외부 이미지나 자료를 사용할 때는 이용 허락과 라이선스를 확인하고 출처 표시 조건을 지킨다.

### 16-1. 화면 디자인 기준

기존 두 시안 중 **개념어 앱 시안의 큰 카드·집중형 구성**을 디자인 기준으로 삼는다. 교과서 복습 앱 시안에서는 위에서 아래로 내려가는 위계형 단원 지도만 살린다. 최종 방향은 다음과 같다.

> **개념어 앱의 큰 카드와 집중감 + 교과서 복습 앱의 위계형 지도 + 밝은 베이지 배경 + 남색 글자 + 초록 선택 상태 + 노란 인출 단서**

#### 화면 구성

- 컴퓨터 전체 화면에서 학습 내용이 작게 보이지 않도록 화면을 넓고 크게 사용한다.
- 단원 지도 화면은 최대 너비 `1200~1280px`, 개념 학습 카드는 `1000~1100px`를 기준으로 한다.
- 메인 학습 카드는 최소 높이 `650~700px`를 기준으로 하되, 내용에 따라 자연스럽게 늘어난다.
- 화면 좌우 여백은 데스크톱에서 최소 `40px`를 확보한다.
- 긴 설명 문장은 카드 전체 너비로 늘이지 않고 실제 읽기 폭을 `700~780px` 안팎으로 제한한다.
- 상단 브랜드와 과목명은 작게 두고, 현재 배우는 개념과 질문이 화면의 주인공이 되게 한다.
- 중앙에는 큰 학습 카드 하나를 두고 `개념 이름 → 핵심 질문 → 구조·도식 → 핵심 설명 → 활동 → 이전·다음` 순서로 배치한다.
- 단계 이동은 개념어 앱 시안의 원형 번호를 사용하되, 숫자 아래에 `장면·구조·비교·적용·설명·검증`처럼 짧은 단계명을 함께 표시한다.
- 남색을 화면 전체에 넓게 칠하지 않고, 주요 버튼·핵심 테두리·글자에 제한해 사용한다.

#### 색상

| 역할 | 색상 | 사용 기준 |
| --- | --- | --- |
| 전체 배경 | `#FFF9EA` | 기존 베이지보다 밝고 맑은 배경 |
| 학습 카드 | `#FFFFFF` | 읽기 영역과 지도 카드 |
| 기본 글자 | `#1D2B3A` | 검정 대신 사용하는 남색빛 먹색 |
| 핵심 버튼·테두리 | `#173A63` | 다음 버튼, 중요한 경계, 현재 단계 |
| 현재 개념·선택 상태 | `#27846C` | 선택한 지도 가지와 핵심 개념 |
| 개념 구조 영역 | `#EAF6F1` | 위계 지도와 설명 도식의 연한 초록 배경 |
| 질문·인출 단서 | `#F4C95D` | 질문, 주의, 예측과 인출 표시 |
| 연한 질문 영역 | `#FFF3C9` | 안내·비교·질문 배경 |

색의 비율은 `밝은 베이지·흰색 70% / 연한 초록 20% / 남색·노랑 강조 10%` 정도로 유지한다. 초록과 노랑을 넓게 남용하지 않아 중학생용 화면이 유아적으로 보이지 않게 한다.

#### 글자체와 크기

- 개념 이름과 핵심 질문에는 `Noto Serif KR`을 사용한다.
- 본문·설명·버튼·안내에는 `Pretendard` 또는 `SUIT`를 사용하고, 불러오지 못할 때는 읽기 좋은 산세리프 계열로 대체한다.
- 명조체는 개념 이름과 질문에만 제한하고 긴 본문에는 사용하지 않는다.

| 요소 | 데스크톱 기준 크기 |
| --- | ---: |
| 개념 이름 | `40~44px` |
| 핵심 질문 | `27~30px` |
| 핵심 설명 | `21~23px` |
| 일반 설명 | `18~20px` |
| 지도 노드 | `17~19px` |
| 안내 문구 | `15~16px` |
| 버튼 | `17~18px` |

모바일과 작은 노트북에서는 미디어 쿼리로 비례 축소하되, 일반 설명은 `16px`보다 작게 만들지 않는다.

#### 위계형 지도 화면

- 처음에는 가장 큰 가지 세 개만 보여 준다.
- 학생이 선택한 가지 하나만 아래로 펼쳐서 글자가 작아지지 않게 한다.
- 현재 가지는 초록색, 선택하지 않은 가지는 흰색 또는 밝은 베이지로 구분한다.
- 상위 개념은 위에, 형제 개념은 같은 높이에, 하위 개념은 해당 부모 아래에 둔다.
- 핵심 질문을 노드 제목으로 사용하고 예시·세부 조건은 마지막 단계에서만 보인다.
- 전체 구조를 한 화면에 억지로 축소해 모든 노드를 작은 글씨로 보여 주지 않는다.

#### 디자인에서 하지 않을 것

- 기존 교과서 복습 앱처럼 상단의 넓은 과목·단계 버튼이 개념보다 더 크게 보이게 만들지 않는다.
- 검정이나 짙은 남색 면을 화면 대부분에 사용하지 않는다.
- 모든 카드와 버튼에 같은 굵기·색의 테두리를 적용해 우선순위를 흐리지 않는다.
- 안내 문구를 개념 이름이나 핵심 설명보다 크게 만들지 않는다.
- 귀여운 장식·이모지·과도한 원색으로 중학생 화면을 유아용처럼 만들지 않는다.
- 전체 지도를 한꺼번에 펼쳐 지도 노드와 설명 글씨가 작아지게 만들지 않는다.

### 16-2. 과학 내용 정확성 검수

앱은 학생의 오개념을 교정하는 도구이므로, 앱 자체가 새로운 오개념을 만들지 않도록 다음 순서로 검수한다.

1. 개념의 정의·조건·대상·방향·원인·결과를 구분해 데이터에 작성한다.
2. `PROJECT_MASTER.md`의 본문과 단원별 진단 기준을 먼저 대조한다.
3. 사용자가 제공한 교재에서는 교육과정 범위와 학습 요소만 확인한다.
4. 기존 앱 데이터와 새 자료가 충돌하면 자동으로 합치지 않고 차이를 기록한다.
5. 같은 용어가 일상어와 교과어에서 다르게 쓰이는지 확인한다.
6. 한 번의 오답과 안정된 오개념을 구분한다.
7. 정의가 맞더라도 조건이나 관계가 빠져 오해를 낳지 않는지 확인한다.
8. 확신할 수 없는 과학 내용은 구현 전에 사용자에게 판단을 요청한다.

「힘의 표현·합력·힘의 평형」 구현에서는 최소한 다음 내용을 서로 혼동하지 않도록 확인한다.

- 힘은 물체의 모양이나 운동 상태를 변화시키는 원인이고, 단위는 `N(뉴턴)`이다.
- 힘의 효과는 모양의 변화와 운동 상태의 변화이며, 운동 상태에는 빠르기와 운동 방향이 포함된다.
- 힘의 크기는 화살표의 길이, 힘의 방향은 화살표가 향하는 방향, 작용점은 화살표의 시작점으로 나타낸다.
- 같은 방향의 두 힘의 합력은 크기를 더하고, 반대 방향의 두 힘의 합력은 큰 힘에서 작은 힘을 뺀다.
- 반대 방향의 합력은 더 큰 힘이 작용하는 방향과 같다.
- 두 힘이 평형을 이루려면 크기가 같고, 방향이 반대이며, 같은 직선 위에서 작용해야 한다.
- 합력이 `0`인 상태와 힘이 전혀 작용하지 않는 상태를 같은 것으로 설명하지 않는다.

## 17. 현재 상태

- 교과 학습 스케줄러의 학습 원리와 1차 MVP 범위를 정리했다.
- 스케줄 생성 로직은 아직 기존 앱 코드와 연결하지 않았다.
- 교과서 복습 앱 ‘다시봄’은 과학 「힘의 작용」과 사회 「인간과 사회생활」 단원까지 구현되어 있다.
- 개념어 앱은 ‘중력’ 한 개념의 6단계 프로토타입까지 구현되어 있다.
- 두 앱을 비교한 결과, 개념 위치 확인·개념 설명·자기 설명·AI 진단·확인 문제 기능이 중복되는 것을 확인했다.
- 개념어 앱과 교과서 복습 앱을 별도 학생용 앱으로 유지하지 않고 하나의 학습 흐름으로 통합하기로 했다.
- 개념어 프로토타입의 6단계 중 어떤 요소를 핵심 개념 카드에 남길지는 시험 중이다.
- 「힘의 작용」 단원의 개념별 정의·필수 요소·대표 오개념·AI 진단 기준을 과학적으로 수정해 이 문서의 부록 A에 통합했다.
- 기존 「힘의 작용」 지도에는 상하 구조가 있으나, 명사형 구조 지도와 질문–답 설명 지도를 하나의 학습 흐름으로 연결하는 방식은 아직 코드에 반영하지 않았다.
- 「힘의 표현」을 학생용 6단계(장면·이름·구조·비교·적용·설명) 카드로 **시범 구현**했다. 아직 시험 전이며 완료가 아니다.
- 「합력」과 「힘의 평형」은 이번 작업에 넣지 않았다. 지도의 말단 노드로만 남아 있다.
- 앱 화면의 색·글자 크기·화면 폭을 16-1 기준으로 옮겼다. 단계 흐름은 기존 네 단계(지도 보기·개념 읽기·개념 말하기·개념 확인하기)를 그대로 두었다.
- 6단계 카드의 `장면`은 앱에 그림을 넣지 않고 교과서 그림과 실물 관찰로 대신한다.
- 구조 지도와 질문–답 설명 지도를 어떻게 전환할지 정하지 않아 지도 화면의 구조는 바꾸지 않았다.

## 18. 현재 확정된 결정

- 학습 기준은 **학교 수업 진도**다.
- 학습 중심 자료는 **교과서**다.
- AI는 **이해·오개념 해결 보조 도구**다.
- 문제집은 **적용과 검증 도구**다.
- 학교 수업 당일에는 **당일 복습을 최우선**으로 한다.
- 아직 배우지 않은 범위는 **짧은 예습만** 한다.
- 핵심 개념은 당일 복습 이후 **약 5회 반복 복습**한다.
- 기본 복습 간격은 **2~3일을 중심으로 점차 확대**한다.
- 복습 회차가 늘수록 **학습 시간을 줄이고 인출 비중을 높인다.**
- 스케줄 생성 로직은 기존 앱에 붙일 수 있도록 **별도 모듈화**한다.
- 개념어 앱과 교과서 복습 앱은 **학생용 별도 앱으로 분리하지 않는다.**
- 교과서 복습 앱을 중심으로 통합하고, 개념어 학습은 앱 안의 **핵심 개념 카드 모듈**로 전환한다.
- 학생에게는 하나의 앱으로 보이게 하되, 개념 데이터·교과서 복습·AI 진단·스케줄러·학습 기록은 코드 내부에서 분리한다.
- 개념어 앱의 기존 기능을 그대로 복습 앱 안에 반복하지 않고, 중복 기능은 한 번만 배치한다.
- 앱의 핵심 교육 목표는 단순 설명이나 정답 확인이 아니라, 학생이 교과 개념어에 잘못 연결한 기존 의미를 발견하고 **정확한 개념 구조로 다시 연결하는 것**이다.
- 학생용 6단계는 **장면 보기 → 개념 이름 붙이기 → 개념 구조 잡기 → 내가 알던 것과 비교하기 → 다른 사례에 적용하기 → 책 덮고 말하고 쓰기**로 구성한다.
- 교사용 세부 설계는 **만남 → 인지 → 이해 → 오개념 비교·교정 → 적용 → 자기 설명 → 인출**의 가젤 스토리를 따른다.
- 정식 문제 검증은 가젤 스토리와 학생용 6단계가 끝난 뒤에 배치한다.
- 짧은 사례 적용과 문제집 풀이는 구분한다. 사례 적용은 표현 전에, 정식 문제 검증은 표현·즉시 인출 뒤에 배치한다.
- `Why → What → How → If`는 개별 화면 수를 정하는 규칙이 아니라 전체 학습 기능을 점검하는 거시 프레임으로 사용한다.
- 자기 설명은 문제보다 먼저 배치하고, 며칠 뒤 **지연 인출**은 스케줄러가 간격 반복으로 배치한다.
- 자기 설명은 완성 답안으로만 보지 않고 학생의 기존 개념 연결을 드러내는 진단 자료로 사용한다.
- 자기 설명을 완전히 없애지 않는다. 개념별로는 짧은 사전·사후 출력으로 사용하고, 단원·수업 범위 전체 설명은 마지막에 한 번 배치한다.
- 당일 복습은 기본적으로 20~30분 안에서 교과서·AI 질문·말하기와 쓰기·소량의 문제 풀이를 배치한다.
- 핵심 한자어에는 한자 뜻풀이를 포함한다. 다만 글자만 기계적으로 풀이하지 않고, 질량·무게·중력처럼 오개념 위험이 있는 개념은 비교 구조 안에서 설명한다.
- 오개념 진단은 단순 키워드 매칭이 아니라 필수 요소·관계·개념 경계·반복되는 오개념 패턴·새 사례 적용을 함께 본다.
- 한 번의 오답은 오개념 후보로 보고, 같은 잘못된 연결이 반복되거나 사전 설명에서 안정적으로 드러날 때 오개념으로 확인한다.
- 공통 진단 원리와 과목·단원별 상세 진단 기준을 모두 이 문서 안에서 관리한다. 상세 기준은 본문을 방해하지 않도록 맨 아래 부록에 둔다.
- 개념 지도는 방사형 마인드맵이 아니라 **위에서 아래로 내려가는 위계형 지도**로 만든다. 깊이는 개념의 우선순위와 포함 관계를 나타낸다.
- 같은 개념 데이터를 **명사형 구조 지도**와 **질문–답 설명 지도**의 두 가지 보기로 사용한다.
- 질문 노드는 학생이 답해야 할 설명 과제로 사용하고, 자기 설명·즉시 인출·간격 반복 복습의 질문으로 재사용한다.
- 교과서와 자습서는 개념·관계·학습 범위를 확인하는 자료로만 사용하고, 앱의 문장·문항·도식·이미지는 독자적으로 제작한다.
- 화면 디자인은 개념어 앱의 큰 카드와 집중형 구성을 기준으로 하고, 교과서 복습 앱에서는 위계형 지도 구조만 가져온다.
- 컴퓨터 전체 화면에서 개념 이름·핵심 질문·설명이 크게 보이도록 데스크톱 화면을 우선 설계한다.
- 과학 내용이 애매하거나 자료끼리 충돌하면 AI가 임의로 판단하지 않고 사용자에게 확인한다.
- 프로젝트 기준과 결정 기록은 별도 파일로 나누지 않고 **이 문서 하나에서 관리**한다.

## 부록 A. 힘의 작용 단원 진단 기준

### A-1. 공통 판정 규칙

- 학생이 특정 단어를 썼는지만 보지 않고, **원인·대상·방향·조건·결과의 관계**가 맞는지 본다.
- 필수 요소가 없으면 `공백`, 일부만 있으면 `부분 이해`, 잘못된 연결이 한 번 나타나면 `오개념 후보`, 같은 연결이 반복되면 `오개념 확인`으로 기록한다.
- 교과서 수준에서 맞으면 우선 통과시키고, 더 정확한 설명은 확장 질문으로 제시한다.
- 오개념 후보에는 정답 문장을 바로 주지 않고 반례·비예시·비교 질문 하나를 제시한 뒤 다시 판단하게 한다.

### A-5. 질량·무게와 운동

질량은 중력의 하위 개념으로 두지 않는다. 질량·무게·중력은 서로 비교해야 하는 독립 개념으로 다룬다.

| 개념 | 핵심 정의·필수 요소 | 대표 오개념 | AI 진단 초점 |
| --- | --- | --- | --- |
| 질량 | 물체가 가진 물질의 양. 단위는 kg이며 장소가 달라져도 변하지 않음 | 질량과 무게를 같은 것으로 봄; 달에서 질량도 줄어든다고 생각함 | 장소 불변성과 kg 단위를 무게와 비교해 확인 |
| 무게 | 중력이 물체에 작용하는 힘의 크기. 단위는 N이며 중력의 크기가 달라지면 변함 | 무게를 kg으로 나타냄; 장소와 관계없이 일정하다고 생각함 | 중력과의 관계, N 단위, 장소 의존성을 확인 |
| 운동 | 기준에 대해 물체의 위치가 시간에 따라 변하는 현상 | 운동과 정지가 기준과 무관한 절대 상태라고 생각함 | 기준·시간·위치 변화를 함께 설명하는지 확인 |
| 속력 | 단위 시간 동안 이동한 거리로 나타내는 운동의 빠르기. 단위는 m/s | 거리만 멀면 더 빠르다고 생각함; 힘이 크면 속력도 항상 크다고 생각함 | 거리와 시간을 함께 고려하고 힘의 크기와 구분하는지 확인 |
| 힘의 작용 | 힘은 물체의 모양 또는 운동 상태인 속력·방향을 변화시킬 수 있음 | 힘은 운동만 바꾸고 모양은 바꾸지 못한다고 생각함; 물체가 계속 움직이려면 진행 방향의 힘이 계속 필요하다고 생각함 | 힘을 원인, 모양·속력·방향 변화를 결과로 연결하는지 확인 |
